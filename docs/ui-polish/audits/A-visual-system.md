# Audit A+D: visual system (geometry, type, colour, surfaces)

Branch `ui/polish-system` (4081a52), classic look as it ships. Auditor A+D. No product file was touched; scratch scripts live outside the repo.

## 1. Scope and method

* **Read in full**: `styles.css`, `tv/tv.css` (2015 lines), `tv/friends.css`, `controller/controller.css`, `controller/friends.css`, `account/account.css`, `polish/base.css` (11 lines: only sets `--ui-look`), `drift/classic.md`, `REFERENCE_PRINCIPLES.md`, `e2e/tv-screens.spec.ts:2325-2405` (the text-floor guard).
* **Measured**: a CSS parser over the six sheets (every authored value with file:line); the 152 scan JSONs (effective type = computed size / `page.em`: 1307 text nodes on the two 1280 TV sets, 1181 on the two phone sets; logo / title / content alignment per screen); pixel samples of the walk pictures; WCAG maths for the six accents on the real surfaces. Every `file:line` below was re-read against the source (paths are under `src/client/`; `friends.css` means `tv/friends.css` unless `controller/` is written).
* **Ran**: my own throwaway server (port 8820, stopped, port confirmed closed) and a scratch Playwright script (not the e2e runner) at 18 sizes around the steps (899 / 900 / 901 x 506, 1280 x 519 / 520 / 521, 915x412, 932x430, 844x390, 1000x562, 1024x576 ...), reading `--em`, logo, hero, row title, tile and corner positions, plus pictures at those sizes.
* **Looked at** pictures of: TV 1280 (home, rail, detail, episodes, search, categories, hub, settings, connect, party, player, menu), 1280 and 1920 signed-in (friends, add friend, settings), 1440x900 and 2560 (home, hub), phone 390 (home, sheets, account, friends), and my own at the breakpoint sizes (in my scratch folder `audit-A/bp/`).
* **Not covered**: ro / it text lengths; mouse hover (CSS only); empty, loading and error screens (not in the walk, code-read only); real hardware; the polish look (not built); motion detail (G), icons (B), control sizes (C), D-pad (E).
* TV sizes below are *effective* (divided by `--em`; nested em compounds): 1.5 means 1.5 % of the screen width at 16:9. `Look`: `both` = bug / state / contrast, `polish` = purely visual.

## 3. Patterns (root causes) and the proposed system

1. **Values are authored inline, no token layer**: 48 TV font sizes, 92 paddings, 17 + 17 radii, 22 greys, 18 durations. Explains A16, A17, A18, A22, A29, A30. The cheapest fix is the token set in 3.2.
2. **White at an alpha is the surface system**: rest, hover and focus fills are 15 alphas on the TV that rebuild two solid greys and leak the page behind. Explains A10, A13, A20.
3. **State language is invented per component**: five focus recipes, five and four "selected" looks, white meaning focus here and selected there. Explains A02, A11, A12.
4. **Red does six jobs** (brand, primary, focus ring, selected, kept, danger) and is the one accent that fails as text. Explains A03, A04, A05, A27.
5. **Page geometry is set per screen, not per template**: logo, title, margins and safe areas differ by page type. Explains A01, A07, A08, A21, A25, A26.
6. **Compaction rules restate the design**: `tv.css:1755-1951` (200 lines) re-declares about 60 sizes, and the flat block was written for phones but fires on 900+ landscapes. Explains A09, A23, A24.
7. **Common kinds are rebuilt each time** (floating surfaces, toasts, states, section headings). Explains A13, A14, A15, A19.
8. **Phone type is a rem continuum** (41 authored sizes, 13 within 12-18.4 px). Explains A06, A17, A19.
