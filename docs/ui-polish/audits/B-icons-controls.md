## 1 Scope and method

- Scope: every control kind on the phone page `/` and the TV page `/tv` (buttons, icon buttons, close and Back, chips, tabs, segmented controls, switches, radio rows, inputs, code inputs, search, sliders, sheets and menus, list rows, cards, badges) and the 46 icons of `src/client/shared/icons.tsx`. Kinds that do not exist: `<select>`, checkbox, `<input type=range>` (sliders are `role=slider` divs); tabs exist only for seasons.
- Pictures opened (`.ui-polish/shots/classic/`): `phone-390/p02-home`, `p04-title-sheet`, `p07-menu`, `p12-remote-playing`; `tv-1280/11-detail-movie`, `25-party-join`, `26-player-hud`.
- Scans and drift: `.ui-polish/scan/classic/*` (sizes of 52 phone control class lists, TV lists at 1280 and 1920) and `docs/ui-polish/drift/classic.md` (icon-size tables, controls under 44 px).
- Own sampler (my scratch folder, not in the repo; my server on port 8821, stopped): keyboard-focused 32 phone and 38 TV controls and recorded computed outline, shadow, background and transform before and after focus. CSS counted per stylesheet: `:active`, `:hover`, `:focus-visible` rules; code grep for `aria-invalid`, `undo`, `spinner`, icon use counts, every `<button className>` site.
- Limits: pressed and hover looks are read from CSS (a headless run cannot press a finger); no Safari or iOS; no real TV. TV numbers are at 1280x720 (1em = 12.8 px; 1920 is an exact 1.5x copy).
- Severity: REFERENCE_PRINCIPLES P1 applies (phone target under 44 px is P1 unless inline text). I measure the control's box, not an `::after` halo, unless I say so. "Look" = `both` (bug, missing affordance, a11y, wrong behaviour) or `polish` (purely visual). Overlaps with the earlier review are marked "also R#n".

## 3 Patterns (root causes)

- BP1 No shared button or control primitives (B11, B15, B16, B22, B24, B25, B26): each screen picks classes by hand, so sizes, colours and states drift. One `Button`, `IconButton`, `Pill`, `Segmented`, `Switch`, `OptionRow`, `ListRow`, `Field` (Appendix C) fixes the whole group.
- BP2 Touch size is solved per component, never once (B01, B04): a hit-area extension exists only on `.lib-round` (42 px with its halo) and `.secret-eye` is drawn 44 px; nothing else reaches 44 except the large buttons. One hit-area rule applies everywhere.
- BP3 One mark carries several meanings (B03, B04, B10, B19, B27): x = close, remove, dismiss, decline, clear, back; check = selected, in list, copied; one red = brand, selected, danger; one icon = several features.
- BP4 State language is invented per component (B05, B06, B07, B13, B14, B16, B17): focus, press, hover, selected, disabled, error each have a different recipe per control; error and loading barely exist.
- BP5 No common safety pattern for irreversible actions (B02, B04, B27): four confirm shapes, no undo.
- BP6 Names written by hand (B08, B23): visible text missing from the name, toggles whose name flips, value pills named by tooltip.
- BP7 A clean icon family without management (B12, B18, B20, B21, B22): sizes scatter, text inside an icon, glyph twins, unused icons.

## 5 Keep
